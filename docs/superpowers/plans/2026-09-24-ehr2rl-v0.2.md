# ehr2rl v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a real, validated, BigQuery-first MIMIC-IV v3.1 pipeline that produces benchmark-grade fluids/vasopressor offline RL datasets for `d3rlpy`.

**Architecture:** Keep `EHRDataset` and `PatientTrajectory` as the core in-memory containers, but add focused modules around them instead of expanding the dataset class. BigQuery access, itemid maps, feature presets, medication actions, rewards, provenance, and the end-to-end example each get their own testable boundary. The local CSV path remains frozen for compatibility.

**Tech Stack:** Python 3.10+, pandas, numpy, scikit-learn, optional `google-cloud-bigquery`, optional `d3rlpy`, pytest, ruff, mypy.

**Spec:** `/Users/bilal/Downloads/ehr2rl v0.2 — Technical Design Document.html`

## Global Constraints

- BigQuery is the primary and only actively developed real-data path for v0.2.
- The local CSV loader remains backward compatible and receives no v3.1 feature or validation work.
- Every BigQuery execution path must dry-run first, compare bytes processed against a configured cap, and set `maximum_bytes_billed` on real jobs.
- Default CI must not require Google credentials or real BigQuery access.
- Real BigQuery tests must be opt-in behind environment variables.
- BigQuery result ordering must be explicit: `ORDER BY subject_id, hadm_id, charttime` for trajectory events.
- Clinical choices such as NEE conversion factors, dose bins, and reward weights must be configurable.
- Exported real datasets must carry provenance metadata as sidecar JSON.
- Keep README and CHANGELOG aligned with the BigQuery-primary / CSV-frozen split.

## Review Focus

- BigQuery billing guard: an over-cap dry run must prevent the real query from being submitted.
- Unordered query results: generated event queries must include deterministic ordering before trajectory construction.
- Itemid drift: a mapped itemid with changed or missing label must fail validation loudly.
- Medication intervals: paused or changed infusion rows must not double-count vasopressor exposure.
- Readmission censoring: admissions near the query horizon must be masked rather than treated as no readmission.
